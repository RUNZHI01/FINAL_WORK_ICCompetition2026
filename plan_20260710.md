# IQ Direct Optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep the Cockpit Desktop one-click path on IQ direct and reduce USRP transport latency without changing the working QPSK path.

**Architecture:** IQ direct remains `cockpit_desktop -> server.py -> usrp_runtime.py -> RunAnalogLatentBatch.py -> persistent TX/RX -> board decode-server -> board-side TVM`. The first implementation pass adds stage-level metrics and guards. Later passes overlap RX capture, board decode, and TVM consumption while keeping the remote decoded directory contract intact.

**Tech Stack:** Python 3, Electron/React Cockpit Desktop, USRP292x persistent control servers, Phytium board Python virtual environment, TVM handwritten operator path, ML-KEM/auth channel, Docker for Linux/bash commands on Windows host.

## Global Constraints

- Do not modify the QPSK runner, QPSK decoder behavior, or QPSK cockpit defaults unless a shared-interface test proves the IQ change broke them. Treat QPSK as the regression baseline.
- Keep the USRP data plane off Tailscale. Tailscale may carry cockpit control, status, SSH, and logs, but IQ sample transport must stay on the direct USRP path.
- Use Docker for bash-driven validation from Windows. If Docker is blocked, use Windows Git Bash. Do not use WSL.
- Keep board login credentials in local environment variables only. Activate the board virtual environment before board-side Python commands: `source /home/user/venv/bin/activate`.
- Keep `JSCC_LINK_MODE=iq-direct` and `transport_mode=usrp` for IQ work. Do not let a previous QPSK run leak into the active state.
- Keep ML-KEM/authentication out of the per-image hot path. Measure security-on overhead separately after the transport path is stable.
- Commit after each completed task. Push after every three new local commits or when explicitly asked.
